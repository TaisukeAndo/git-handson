# 物語リレー（Git ハンズオン用リポジトリ）

アプリ開発エージェント構築セミナー（session2）で、Git と GitHub の操作を、**自分でコマンドを打って**体験するための練習用リポジトリです。

ルールは簡単です。**グループごとに、1人1文ずつ、物語の続きを書いていきます。**
最後の人にバトンが渡ったとき、物語が完結します。

## 全体の流れ

グループごとに、`stories/` フォルダの中に物語のファイルがあります（第01グループなら `stories/story-01.txt`）。
物語の書き出しは、2文だけ書いてあります。**自分の順番が来たら、前の人の続きを1文だけ**書き足します。

| 自分の順番 | 前の人の PR | 自分のやること | 自分の PR をマージする人 |
|---|---|---|---|
| 1番目 | なし | 書き出しの続きを書く | 2番目の人 |
| 2番目以降 | **自分が、最初にマージする** | 前の人の続きを書く | 次の人 |
| 最後の人 | 自分が、最初にマージする | 物語を「おしまい。」で終わらせる | **1番目の人** |

**前の人の PR がマージされるまで、書き始めない**でください（マージされる前に書くと、前の人の文と
ぶつかります。直し方は、このページの最後にあります）。

## 事前に必要なこと

- GitHub のアカウントがある
- 講師から、このリポジトリへの招待（collaborator）が届いている。GitHub の通知かメールから承認してください
  - 承認しないと、Push と、他の人の PR のマージができません
- パソコンで、`git` が使える（ターミナルで `git --version` と打って、バージョンが出れば大丈夫です）
- Git に、名前とメールアドレスを登録してある（`git config user.name` で名前が出れば大丈夫です）
- 講師から、**グループの番号**と**自分の順番**、そのグループの**人数**を聞いている

ターミナルは、Mac は「ターミナル」、Windows は「PowerShell」を使います。

## 最初に1回だけ：リポジトリを取得する（clone）

順番を待っている間に、済ませておきます。

```bash
git clone https://github.com/TaisukeAndo/git-handson.git
cd git-handson
```

- `git clone` は、GitHub のリポジトリを、自分のパソコンにコピーするコマンドです
- `cd git-handson` は、コピーしたフォルダの中に移動するコマンドです

## 自分の番になったら

以下の例は、**第01グループの2番目**の人の場合です。自分のグループの番号と順番に読み替えてください。

### 1. 前の人の PR を、GitHub でマージする（2番目以降の人）

1. ブラウザで、このリポジトリのページを開く: https://github.com/TaisukeAndo/git-handson
2. 上のタブの「Pull requests」を押す
3. 前の人の PR（タイトルに「第01グループ 1番目」のように書いてあります）を押す
4. 「Files changed」タブを押して、変更を確認する
   - 緑色で表示された行が、前の人が書き足した1文です
   - 物語の続きとして、**1文だけ**が足されているかを見ます
5. 「Conversation」タブに戻り、「Merge pull request」ボタンを押す
6. 「Confirm merge」ボタンを押す

1番目の人は、この手順はありません（2番目の人が、1番目の人の PR をマージします）。

### 2. 最新の状態を取得する（pull）

```bash
git switch main
git pull
```

- `git switch main` は、公開されている版（main）に切り替えるコマンドです
- `git pull` は、GitHub の最新の状態を、自分のパソコンに取り込むコマンドです。
  **前の人の文が入っていることを、次の手順の前に確認してください**

```bash
cat stories/story-01.txt
```

物語が最後の行まで表示されます。これを読んで、続きを考えます。

### 3. 自分用のブランチを作る（branch）

```bash
git switch -c story-01-02
```

- ブランチは、ファイル一式のコピーを作って、そこで作業するための仕組みです
- 名前は、`story-グループの番号-自分の順番` にします（第01グループの2番目なら `story-01-02`）

### 4. 物語の続きを書く（編集）

1. テキストエディタ（メモ帳、VS Code など）で、自分のグループのファイル（`stories/story-01.txt`）を開く
2. **いちばん最後の行の次に、新しい行を作って、1文だけ**書く
   - 前の人の文の続きになるように書きます
   - 他の行（`#` で始まる行や、前の人の文）は、変えません
   - 最後の人は、物語を「おしまい。」で終わらせます
3. ファイルを保存する

### 5. 変更を確認する

```bash
git status
git diff
```

- `git status` は、変更したファイルの一覧を見るコマンドです。`stories/story-01.txt` だけが出れば大丈夫です
- `git diff` は、変更の中身を見るコマンドです。緑の `+` の行が、自分が書き足した1文だけであることを確認します

### 6. 変更を記録する（add、commit）

```bash
git add stories/story-01.txt
git commit -m "第01グループ 2番目の文を追加"
```

- `git add` は、「この変更を記録の対象にする」と指定するコマンドです
- `git commit` は、変更の記録を1つ残すコマンドです。`-m` のあとの文章が、記録の名前になります

### 7. GitHub に送る（push）

```bash
git push -u origin story-01-02
```

- `git push` は、自分のパソコンの記録を、GitHub に送るコマンドです
- 成功すると、「Create a pull request for 'story-01-02' on GitHub by visiting:」と出て、URL が表示されます

### 8. プルリクエスト（PR）を作る

1. push のあとに表示された URL を、ブラウザで開く
   - 表示されなかったときは、リポジトリのページを開くと、黄色い帯に「Compare & pull request」ボタンが出ます
2. 「Compare & pull request」ボタンを押す
3. タイトルに、`第01グループ 2番目` のように、グループと順番を書く
4. 「Create pull request」ボタンを押す
5. 次の人に、「PR を出しました」と声をかける

次の人が、あなたの PR をマージして、続きを書きます。
**最後の人の PR は、1番目の人がマージします。**

## 完成した物語を読む

最後の人の PR がマージされたら、全員で、自分のパソコンに最新の状態を取り込みます。

```bash
git switch main
git pull
cat stories/story-01.txt
```

グループで、完成した物語を、声に出して読んでみてください。

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| `git push` で、権限エラーが出る | collaborator の招待を承認したか。GitHub にログインできているか |
| `git commit` で、名前を聞かれる | `git config --global user.name "自分の名前"` と、`git config --global user.email "メールアドレス"` を実行する |
| `git switch -c` で、「すでにある」と出る | ブランチ名が、自分のグループと順番になっているか確認する |
| PR の画面に、「conflict」（競合）と出る | 前の人の PR がマージされる前に書き始めた可能性がある。講師に声をかける（直し方は下） |
| 前の人の文が、`cat` で見えない | 前の人の PR がマージされていない。待つか、声をかける |

### 競合（conflict）を直す方法

前の人のマージを待たずに書き始めると、自分の文が、同じ場所に書かれた別の文とぶつかります。
次の手順で、**自分の文だけを書き直して**、やり直します。

```bash
git switch main
git pull
git switch -c story-01-02-retry
```

エディタで、`stories/story-01.txt` の最後に、自分の1文を**もう一度**書いて、保存します。
そのあと、手順6（add、commit）と手順7（push）を、新しいブランチ名で行い、新しい PR を作ります。
古い PR は、「Close pull request」で閉じます。
